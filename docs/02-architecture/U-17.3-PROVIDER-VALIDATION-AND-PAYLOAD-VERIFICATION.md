## 0. What actually happened, and the account/credential boundary

The founder created real trial accounts with both shortlisted providers and supplied API keys via a local, untracked `.env` (`SPORTMONKS_API_KEY`, `THE_ODDS_API_KEY` — documented, unset by default, in `.env.example`). A disposable, temporary script (`storage/tmp-qa/validate-providers.php`, gitignored, never committed, never referenced by the production application) made real, authenticated requests against both providers' live APIs and saved redacted samples locally (`storage/tmp-qa/provider-samples/`, gitignored — not committed, since neither provider's redistribution terms were confirmed permissive enough to commit raw payloads to a public-adjacent repository). Every finding below comes from a real HTTP response, not documentation or marketing copy — this is exactly the gap `U-17.2` identified and could not close on its own.

**No production code was touched. No migration was written. No credential was committed.**

## 1. Executive Recommendation

## **NARROW — proceed with The Odds API as the primary MVP market/odds source; SportMonks' free tier could not validate the target leagues**

This is a materially more specific and more favorable finding than `U-17.2`'s desk-research-only NARROW — real trial data now confirms 7 of 9 `FootballMarketTaxonomyV1` market families are genuinely available and well-structured from one provider (The Odds API), on its free tier, for the actual leagues SlipGuard would need. ## 2. SportMonks — real trial findings

**Coverage gap found immediately, not assumed**: the trial account is on SportMonks' Free Plan, which — confirmed by inspecting the real `leagues` endpoint response — covers only 2–4 minor leagues (Scottish Premiership and an unidentified "Superliga," not the top-five European leagues `U-17.2` assumed as the MVP target). A live fixtures-by-date-range call returned real fixtures, but they were Scottish Premiership fixtures (e.g. "Dundee United vs Rangers"), not EPL/La Liga/Serie A. **This means SportMonks' fixture/competition coverage for the actual MVP target leagues remains unverified — the free tier cannot confirm it, and validating it would require upgrading to a paid plan (Starter, €29/mo, "pick any 5 leagues" per `U-17.2`'s own pricing research), which this work package did not authorize as a spend.**

**Structural quality, where it could be observed, is genuinely good**: fixture records carry stable-looking numeric IDs, ISO-ish timestamps (`starting_at`, `starting_at_timestamp`), a `state_id` lifecycle field, and richly-structured `participants` (team) sub-objects with their own stable IDs, country, founding year, and per-fixture `meta.location`/`meta.winner` context — a genuinely well-designed schema, not a thin wrapper. A real single-fixture odds sample (`odds.market;odds.bookmaker` include) returned rows with a machine-readable `market.developer_name` (e.g. `FIRST_10_MIN_WINNER`) alongside a human `market.name`, plus `label`/`value` (selection/decimal odds) and full `bookmaker` attribution — this is a clean shape to build a canonical-market mapping against, once the right leagues are actually reachable.

**Confirmed present in the sample, by real market name** (a small, randomly-truncated 30-row slice of what is likely a much larger per-fixture set): "Fulltime Result," "Half Time Result," and "Exact Total Goals" — consistent with `FootballMarketTaxonomyV1`'s Match Result, Half-Time Result, and Total Goals families respectively, though this pass did not isolate and confirm every family by market ID (a `/markets` catalogue endpoint was guessed and returned `404` — the real endpoint name was not found in this pass and should not be assumed from the guess alone).

**Nigeria/NPFL check: inconclusive, not negative.** A `leagues/search/Nigeria` call returned zero results with a message stating explicitly that this could mean either no such league exists in SportMonks' catalogue *or* the account's current subscription simply doesn't grant access to it — the API itself does not distinguish these two cases, and this trial cannot either.

## 3. The Odds API — real trial findings, and the important discovery

**The single most valuable finding of this work package**: the bulk `/v4/sports/{sport}/odds` endpoint only accepts `h2h` and `totals` as market keys for European regions — requesting `btts`, `draw_no_bet`, or `double_chance` on that endpoint returns a real `422 INVALID_MARKET` error. This directly contradicts the confident-sounding marketing language `U-17.2` cited ("The Odds API covers soccer odds for... Both Teams to Score"). **The marketing claim is not false, but it is incomplete in a way that matters architecturally**: those markets exist, but only through the *per-event* endpoint (`/v4/sports/{sport}/events/{eventId}/odds`), which requires one authenticated request per fixture rather than one bulk request per league. Confirmed by directly querying that endpoint for a real upcoming Arsenal fixture:

- `btts` → real data returned (`Yes`/`No`, decimal prices, per bookmaker — e.g. 1xBet: Yes 2.49 / No 1.48)
- `draw_no_bet` → real data (team names only, no draw outcome — e.g. Coral: Arsenal 1.03 / Coventry City 11)
- `double_chance` → real data ("Arsenal or Draw," "Coventry City or Draw," "Arsenal or Coventry City" outcomes)
- `h2h_h1` (first-half result) → real data, 3 bookmakers
- `correct_score` → real data, 1 bookmaker
- `h2h_h2` (second-half) and `team_totals` → valid market keys, but **zero bookmakers had priced them yet** at several days out from kickoff — an availability/freshness finding, not an incompatibility one
- No working key was found for a combined Half-Time/Full-Time market in this pass — genuinely unconfirmed, not asserted absent

**Taxonomy mapping (real, not assumed)**:

| `FootballMarketTaxonomyV1` family | The Odds API market key | Confirmed via real request | Shape |
|---|---|---|---|
| Match Result | `h2h` | Yes (bulk endpoint) | `outcomes[]`: team name / team name / `"Draw"`, decimal price |
| Double Chance | `double_chance` | Yes (per-event endpoint) | `outcomes[]`: `"X or Draw"` / `"Y or Draw"` / `"X or Y"` |
| Draw No Bet | `draw_no_bet` | Yes (per-event endpoint) | `outcomes[]`: team name, team name only |
| Total Goals | `totals` | Yes (bulk endpoint) | `outcomes[]`: `"Over"`/`"Under"` + a numeric `point` line value |
| Both Teams to Score | `btts` | Yes (per-event endpoint) | `outcomes[]`: `"Yes"`/`"No"` |
| Correct Score | `correct_score` | Yes (per-event endpoint) | valid, one bookmaker priced at trial time |
| Half-Time Result | `h2h_h1` | Yes (per-event endpoint) | same shape as `h2h`, scoped to first half |
| Team Total Goals | *(not identified)* | Not confirmed | `team_totals` key accepted but returned no priced bookmakers in this pass |
| Half-Time/Full-Time | *(not identified)* | Not confirmed | no working key found in this pass |

Seven of nine families confirmed with real data; two remain open, not because they're proven unavailable but because this bounded trial didn't surface a working key or priced data for them.

**Coverage confirmed, not assumed, for the actual MVP-relevant leagues**: real odds were returned for EPL, La Liga, and Serie A specifically (the three tested) via the free tier — a materially stronger, verified result than SportMonks' free-tier coverage gap above.

**African/Nigerian coverage: confirmed absent, not merely unknown.** The full list of active soccer sport keys was fetched and enumerated in this pass — every entry inspected, none named a Nigerian or other African competition. Unlike the SportMonks case, this is a real negative finding, not an inconclusive one, since the full catalogue (not a subscription-gated subset) was checked.

**Credit cost observed directly**: each per-event, per-market request consumes real quota (`x-requests-remaining` header dropped from 500 toward roughly 460 over the course of this validation's dozen-odd requests) — confirming the commission's own §18 concern that per-event market access is not free relative to the bulk endpoint, a real operational-cost data point for whoever eventually sizes a production integration.

## 4. Odds MVP decision (§19 of the commission)

**Option A — Odds Included in MVP, via The Odds API specifically** is now the best-supported option of the four named, based on real evidence: structured, per-market, per-bookmaker odds with real EPL/La Liga/Serie A coverage exist today, on a free tier, mapping cleanly to seven of nine taxonomy families. This reverses `U-17.2`'s more cautious framing (which had not yet ruled out Option C, "no odds targeting"). The two-family gap (Team Total Goals, Half-Time/Full-Time) means a first construction pipeline should scope its supported markets to the seven confirmed families, not assume full taxonomy parity.

## 5. Single vs. dual provider (§24)

**Dual provider remains the honest answer, but asymmetric to what `U-17.2` assumed.** The Odds API is now the stronger candidate for *both* fixture-level odds/market data (confirmed) *and* basic fixture identity (each event payload already carries `home_team`/`away_team`/`commence_time`), which may reduce or remove the need for a second provider purely for fixture scheduling. SportMonks remains the stronger candidate specifically for *richer* competition/team metadata (founding year, country, venue, position) if that depth is ever needed beyond what construction eligibility requires — but this was not verified for the actual target leagues in this trial, only for two Scottish/minor leagues the free tier happened to expose.

## 6. Licensing — unchanged from `U-17.2`, still the real blocker

This work package did not, and could not, resolve the licensing question `U-17.2` raised (API-Football's explicit betting-platform licensing caveat). The Odds API's and SportMonks' own full terms of service were not exhaustively reviewed in this pass (that remains Compliance Office's task, per `U-17.2` §7/§33) — a provider proven technically compatible here is not thereby proven legally clear.

## 7. Recommendation and handover

**GO, narrowed**: proceed to Compliance Office review of The Odds API's full terms of service specifically (not a generic survey of all four candidates — this trial has now identified it as the clear front-runner), focused on: derived-analysis rights (does displaying a customer-facing structural score built from this odds data require anything beyond the standard commercial tier), caching/storage duration, and whether "betting platform" language exists anywhere in its terms even though none was found in its public marketing pages. If Compliance clears it, Architecture Office should revisit `U-17.1`'s provider-abstraction design (§6) with this document's real payload shapes in hand — the per-event-request cost finding in particular affects the caching/freshness strategy assumptions there.
