Not fixed here (editing `docs/05-ux/` is outside this commission's authorized scope) — named so a future reader of `HOMEPAGE_STORYBOARD.md` isn't misled by its literal wording.

## 1. Section-by-section composition (desktop / tablet / mobile)

All eight sections use `container-marketing` (1280px max-width) with `px-6` horizontal padding, matching `DESIGN_TOKENS.md`'s real definition. Vertical rhythm for standard sections is `py-16 sm:py-20` (mobile tightest, desktop full) — consistent with `RESPONSIVE_RULES.md`'s "section gaps use the larger end on desktop, tightest on mobile" rule.

### Hero

- **Desktop (`lg`+):** two-row structure — Row One: copy (left) + primary/secondary actions (right) in a 12-column grid (`grid-cols-1 lg:grid-cols-12`); Row Two: full-width real Demo Workspace dashboard screenshot in a bordered, elevated frame (`hero-dashboard-frame`, `shadow-elevation-2`), with the one-time `light-sweep` reveal already reviewed and adopted under `PO-U15.4-001`/`PO-GOV-UX-002` (specialist-tool consultation already performed and disclosed inline in the file itself — genuinely reused, not re-litigated here).
- **Tablet:** Row One collapses to `grid-cols-1` (copy stacks above actions); Row Two screenshot remains full-width, scaled down proportionally.
- **Mobile:** identical stacking; actions become full-width buttons (`w-full sm:w-auto`); the dashboard screenshot uses the already-built two-view touch-draggable canvas (`Public Mobile Header and Homepage Hero`, delivered — real, not proposed here).
- **Component mapping:** primary/secondary action buttons are currently hand-rolled inline markup, not `<x-primary-button>`/`<x-secondary-button>` — flagged again here as the same real duplication `U-20.6` found (§4).

### Invisible Risk (Problem)

- **Desktop:** illustrated sample-accumulator card, `grid-cols-1 lg:grid-cols-12`, structural-comparison element with a real MSC-derived contribution indicator (not an invented percentage — inline comment confirms).
- **Tablet/Mobile:** single column; the 5-item comparison row (`grid-cols-1 sm:grid-cols-5`) drops to a stacked list below `sm`, each item full-width (`flex sm:flex-col`).
- **Screenshot use:** none — illustrated, not a product screenshot, matching `HOMEPAGE_STORYBOARD.md` §2's own "a single, plain illustration... not a chart, not a real slip screenshot" rule.

### How SlipGuard Thinks (Solution)

- **Desktop/Tablet/Mobile:** the evidence→rules→conclusion sequence renders as a bordered, elevated card (`bg-surface-card`, title-bar strip pattern matching `HOMEPAGE_STORYBOARD.md` §39's "treated as a piece of software, not a floating marketing card"), full-width at all breakpoints, internal content reflowing via existing `sm:` steps.

### Proof (Intelligence Credibility)

- **All breakpoints:** `bg-surface-inverse`/`bg-gradient-inverse` — the one intentionally inverted-tone section (matches `HOMEPAGE_STORYBOARD.md`'s "Proof — unchanged content" note). Verified count-based metrics (test counts, not fabricated stats), consistent with `R-01.8` §6's trust table.

### How It Works

- **Desktop:** three-step layout, `grid-cols-2 sm:grid-cols-3` for the summary strip beneath — worth flagging: this grid starts its multi-column behavior at `sm` (640px), earlier than `RESPONSIVE_RULES.md`'s general tablet-vs-mobile guidance would suggest for a 3-item row; kept as-is since three short items at `sm` width don't cramp, and changing it isn't authorized (no layout changes beyond specification here — see §4 for what actually changes).
- **Mobile (below `sm`):** two-column grid for the summary strip, single column for the three main steps.

### Product Capabilities

- **Desktop/Tablet:** `grid-cols-1 sm:grid-cols-3` — three `<x-card variant="interactive">` deep-links (Analyse/Reports/Planner), each with an icon, title, one-line description, "Learn more" affordance. **No screenshots here** — icon-based, confirmed directly (§0). Remaining authenticated-only capabilities (Journal, History, Weakest-Leg, Customer Control, No Prediction) are named-only, unlinked — already correct per `R-01.9`'s own review, not changed.
- **Mobile:** single column, cards stack full-width.

### Trust

- **All breakpoints:** centered `max-w-2xl` text block, no layout complexity — matches `HOMEPAGE_STORYBOARD.md` §5's "short, calm statements... no badges, seals" instruction exactly.

### Final CTA

- **Desktop:** `flex-col sm:flex-row` — single primary action + a secondary text link ("View pricing"), never two primary-styled buttons, matching `COMPONENT_PRINCIPLES.md`'s "exactly one primary per screen" and `HOMEPAGE_STORYBOARD.md`'s closing-CTA rule.
- **Mobile:** stacked, full-width primary action.
