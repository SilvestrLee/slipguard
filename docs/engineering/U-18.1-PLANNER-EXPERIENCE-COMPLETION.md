## Authority and boundaries

The Product Office amendment resolved the original `U-17.6` identifier collision and established this work as U-18.1. Programme U-17 remains constitutionally closed.

This implementation retains:

- the existing market-evidence provider abstraction;
- the existing feature-gated provider integration;
- the existing public-launch and compliance gates;
- the accepted deterministic construction and Planner architecture;
- the Sprint 9 shell and SlipGuard Design Language.

It does not enable the feature flag, add a provider, broaden provider use, change deterministic calculations, change persistence, or authorise public release.

## Repository audit

### Confirmed as already implemented

- Planning brief controls and repository-backed request summary.
- Deterministic fixture and market eligibility.
- Customer outcome sovereignty.
- Whole-candidate structural evaluation.
- Candidate acceptance into a persisted Planner session.
- Planner session editing, locking, regeneration and history.
- Provider-boundary failure containment and preserved planning choices.
- No-candidate, empty-pool and provider-unavailable distinctions.
- Responsive authenticated-workspace adoption.

### Confirmed gaps

1. Candidate discovery displayed a timer-driven percentage and advanced staged messages every 750 milliseconds. Those values did not observe repository lifecycle boundaries and violated truthful-progress requirements.
2. The Builder landing experience did not surface recent planning sessions or an explicit capability-status context, weakening continuity between candidate discovery and Planning History.

## Implementation

- Removed the timer, percentage, staged-message interval and artificial progress-bar width.
- Added a single honest in-request status report describing the actual work performed by `BuildAccumulatorCandidate`.
- Explicitly states that no percentage is shown because remaining work cannot be measured truthfully.
- Retains a reduced-motion-compatible active indicator and polite live-region announcement.
- Added the authenticated customer’s three most recently updated Planner sessions to the Builder landing experience.
- Added real session status, source-slip identity, selection count and direct links to the saved session and Planning History.
- Added a repository-backed empty state when no planning sessions exist.
- Preserved user ownership boundaries in the recent-session query.
